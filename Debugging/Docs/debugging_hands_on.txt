9. Finding "Hidden" Latency with Thresholds
Goal: Automatically capture a trace only when a specific latency threshold is exceeded.
Reset and set function tracer:
 $ echo function > /sys/kernel/tracing/current_tracer
Set a latency threshold (e.g., 50 microseconds):
 $ echo 50 > /sys/kernel/tracing/tracing_thresh
Enable the "display-graph" option:
 # echo 1 > /sys/kernel/tracing/options/funcgraph-proc
 If any function takes longer than 50µs, it will be recorded in the trace file.

KGDB for Kernel Debugging
-------------------------
1. Exit the minicom as the port would be used for debugging & login using ssh
$ ssh root@192.168.7.2
2. Trigger the kgdb
$ echo ttyS0 > /sys/module/kgdboc/parameters/kgdboc
$ echo g > /proc/sysrq-trigger (This would trigger the kgdb and ssh would freeze)
3. On the Host
$ sudo chmod 666 /dev/ttyUSB0
$ arm-none-linux-gnueabihf-gdb <path to buildroot>/output/build/linux-6.6.63/vmlinux
$ target remote /dev/ttyUSB0
This would attach the debugger to the target
$ b vfs_read
$ c (This would break at vfs_read)
$ n (Next instructions)

KGDB for Debugging the Existing Kernel Module
---------------------------------------------
1. Exit the minicom as the port would be used for debugging & login using ssh
$ ssh root@192.168.7.2
2. Load the Kernel Module (Should be compiled with -O0 optimization and -g flag) 
$ insmod buggy.ko
3. Retrieve the address of the section namely '.text', '.data', and '.bss' (optional)
 $ cd /sys/module/buggy/sections/
 $ cat .text .data .bss
 
4. Trigger the kgdb on Target
$ echo ttyS0 > /sys/module/kgdboc/parameters/kgdboc
$ echo g > /proc/sysrq-trigger (This would trigger the kgdb and ssh would freeze)
5. On the Host
$ sudo chmod 666 /dev/ttyUSB0
$ arm-none-linux-gnueabihf-gdb <path to buildroot>/output/build/linux-6.6.63/vmlinux
$ target remote /dev/ttyUSB0
6. Add module addresses to the GDB with command
<gdb> add-symbol-file buggy.ko 0xbf031000 -s .data 0xbf033000 -s .bss 0xbf0333c0
7. Set the breakpoint in the module with
 <gdb> b buggy.c:my_read
 <gdb> c
8. On the target, try 
 $ cat /dev/debug
This should hit the breakpoint

Using perf
----------
 + For installing perf, use perf use:
 sudo apt install linux-tools-common linux-tools-generic linux-tools-$(uname -r)
 
 + If you frequently update your kernel, you can install the generic metadata package which attempts to keep the tools in sync:
sudo apt install linux-tools-generic

+ If you run perf and see a warning that it is not found for your kernel version, it usually means the package for your exact kernel is missing from the repository. In this case: 
List available versions: apt search linux-tools
Manual Linking: If a "close enough" version is installed, you can manually link it:
sudo ln -s $(find /usr/lib/linux-tools/*/perf | head -1) /usr/local/bin/perf

5. Verification
Confirm the installation was successful by checking the version:
perf --version

+ perf-top
+ sudo perf top -p [PID]
+ sudo perf top -s comm,dso,symbol
